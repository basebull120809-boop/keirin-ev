# keirin-ev 競輪 期待値投資システム

「当てる」ではなく「オッズが確率より高い目だけを買う」ためのシステム。
GitHub Actions 上で自動実行するので、PCは不要（スマホのGitHubアプリで結果を見る）。

## 見る場所
- **reports/latest.md** … 毎晩更新されるレポート（取得状況・人気別回収率・検証結果）
- **アクション** タブ … 自動実行の成功/失敗

## 自動で動くもの
| 名前 | タイミング | 内容 |
|---|---|---|
| collect | 毎日 01:40 | 前日・前々日の出走表・3連単確定オッズ・結果を取得 → レポート更新 |
| backfill | 毎日 13:10 / 19:10 | 過去に7日ずつ遡って取得（2024-11-01まで）※変数 BACKFILL_ON=true で有効 |
| live | 08:15 / 13:55 / 19:35 起動 | 締切6〜1.5分前にオッズを取り直して期待値判定 → 買い目を「買い目 日付」のIssueに投稿 |
| probe | kdreams.py 更新時 | 取得テスト。debug/ に結果を保存 |
| nk-backfill | 04:40 / 10:40 / 16:40 / 22:40 | ネット競輪「データ分析」が未取得の日を新しい順に3日分（1日 約40分） |

## ネット競輪のデータ分析（keirin_ev/netkeirin.py）
- 選手ごとの条件別成績（過去3年）から、今回の条件に当たる行の1着率を特徴量にする
  （レース種目・周長・見なし直線・この場・今回の位置・時間帯・日程・グレード・同県同乗の9つ、`p_nk_*`）
- 過去レースのページも「そのレース時点」の集計（同じ開催で日ごとに出走回数が1ずつ増えることを確認）
- 取得は1レース9回・2秒間隔。collect（前日分）と nk-backfill（過去分）が data/daily/…/nk_data.csv.gz に保存
- 当日運用では判定のときにそのレースの分を取る。取れなければこの特徴量なし（0）で判定

※ live は1日約16時間動くため、非公開リポジトリでは無料枠（月2,000分）を超えます。
自動起動はリポジトリを公開にしたときだけ有効（手動実行はいつでも可）。

## 当日運用
- 設定は **config.json**（mode: paper=紙上運用 / 資金 / 期待値の基準など）
- 買い目は Issue「買い目 YYYY-MM-DD」にコメントで届く（GitHubアプリの通知をオンに）
- 締切8分後からレース結果を見に行き（3分おき・最大90分）、data/live/日付/results.csv に取り込む
  → その日のうちにページの成績に反映（翌朝の collect で確定データに置き換わる）
- 判定した買い目と締切前オッズは data/live/日付/ に保存し、翌朝の結果と突き合わせて
  reports/latest.md の「当日運用」欄に実績を出す
- **このシステムは購入しない。** 買うかどうかは通知を見て自分で判断する

## 券種の使い分け（2車複・ワイド・2車単・3連複・3連単）— 2026-11-18 改訂
- 1点勝負・絞った買い方はしない。展開シナリオ予想の確率で、判定のたびにそのレースを **1000回シミュレーション**
  （ラインごとの展開の揺らぎ＝主導権を取れた／沈んだ、番手が残った／千切れた、などを込み）し、
  **一番多くの回で当たる買い方を1つ** おすすめにする
- 候補（確率の高い順に上から）：2車複・ワイド 2〜4点／2車単 3〜6点／3連複 4〜10点／3連単 10〜20点
- 合成オッズ2倍未満・見込み回収80%未満の買い方は使わない（そういう買い方しか組めないレースは見送り）
- 一番来そうな目が元返し（1.0倍）の券種は候補から外し、残りの券種で判定する（2026-11-22 改訂：前はレースごと見送りで、1日4〜10R減っていた）
- 金額は どの目が当たっても投資額×1.7倍以上が戻る配分。できなければ見送り
- 過去検証（2026-09〜11・2,273R、確定オッズ）：685R 的中39%・回収84%・平均5.4点
  （前の「見込み回収最大」は 的中27〜30%・回収97% だったが1点勝負が多く、やめた）
- ワイドは今日から判定時オッズ（odds_live_wide）と払戻（wide_combos／wide_payouts）を記録中。読み取りは確認済み
- 仕組みは keirin_ev/bettypes.py の multi_plans / multi_pick、keirin_ev/simulate.py

## データ
`data/daily/年/月/日付/` に races / entries / results / odds_trifecta の4つのCSV(gzip)

## 仕組み
1. 1着モデル：競走得点・勝率・連対率・ライン位置・短走路×先行・風×先行・市場の1着確率
   ＋いろんな視点（keirin_ev/perspectives.py）：S・B回数、番手から見た前の先行力、自力型×先頭、差し型×番手、
   番手巧者（過去に番手で市場の見積もりを上回った回数）、上がりタイム、調子（直近の着順）、地元
   ＋独自の視点：今場所の調子、ギヤ変更、先行争い（他ラインの先頭のB）、ラインの厚み、番手の格上度、
   今日のバンク（同じ場・同じ日のそれまでのレースで先頭・番手のどちらが勝っているか）
   ＋Kドリームスの記者予想（アオケイ）：予想印・総評・好気合・展開予想の戦法（先行／押え先）・選手コメント
     （出走表と同じページから取得。過去分は backfill の中で yosoufill が1回3日ずつ取り直す）
   ※データが少ないうちは視点の効きを強めに縮める（約5,000レースで通常の強さ）。H（ホーム）回数は出走表に無いので未使用
2. 2・3着モデル：同ラインの連動を数値化
3. 市場ブレンド：log p = a·log(モデル) + b·log(市場)（市場を事前分布にしたベイズ更新）
4. 点数：10〜20点（3連単1番人気のオッズが低いほど少なく、40倍以上で20点）。1番人気10倍未満の硬いレースは6点
5. 選び方：期待値（確率×オッズ）の高い順。1着候補は最低2人
6. 配分：どれが当たっても払戻がそろうように1レース3,000円を配分
7. 見送り：選んだ組全体の期待値（的中率×合成オッズ）が1.10未満なら買わない
（数値はすべて config.json で変更可）

**判定基準：検証の回収率95%区間の下限が1.0を超えるまで実弾は入れない。**

データ取得元: Kドリームス（個人利用の範囲・アクセス間隔2秒以上）
